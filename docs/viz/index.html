缺的數據（不補就不能宣稱）

  • macOS 預設 vs cool42 同負載穩態：A/B 只有兩條 cool42 曲線，沒有「原廠自動」組。原廠 105–107°C / ~2,100 rpm / P-core 3300–3800 MHz 是外部網路資料。待補：perf_vs_temp.py（需 sudo＋空機）。
  • B 段內的時脈與 pressure：powermetrics 9 筆都在 A/B 5 分鐘視窗外，而且都在 A 曲線生效時（A 段前 05:00:41–47；B 結束、ab.sh 還原成 A 之後的 05:19–05:20）。要主張「B 不降頻」需重做 A/B 並在段內同步記錄。
  • 同一工作總耗時：沒量過，不能宣稱「快 X%」。
  • 真的降頻 → hook 等待 → 恢復放行：近 4 天 0 次，沒有實例可展示主打功能的「等」那一段；需受控重現。
  • A/B 期間的降頻秒數：當時 guard 尚未記錄 throttleSeconds；9/9 Nominal 是 A 曲線時的取樣，不能代替 B 段。
  • 等間隔溫度時間序列：log 只在寫 SMC 時記錄；history.json 只留 5 分鐘。分布圖不能當時間佔比。
  • n=1 台 Mac mini M4；09-20 之前的 log 已不在，README／CHANGELOG 的歷史數字只能照文件引用。
